# Windows EXE 실행 및 패키지 구성 개선

사용자 요청: 압축 해제 후 실행 파일을 쉽게 찾고 EXE 더블클릭으로 사용하며, 내부 파일은 용도별로 정리하고 릴리즈를 업데이트한다. 폴더 구성과 구현 판단은 사용자에게 위임받았다.

## 선택

기존 self-contained 수집기와 운영 등록 계약을 유지하고, 최상위에 작은 Windows 네이티브 실행기 `AirWaveAPMonitor.exe`를 추가한다. 실행기는 자신의 위치를 기준으로 `app/AirWaveApMonitor.App.exe --desktop true`를 새 콘솔에서 시작한다. 별도 런타임 설치나 PowerShell 실행 정책 변경은 필요 없다. 두 번째 .NET 런타임을 포함하는 독립 런처, 설치 프로그램, 트레이 관리 화면은 이 요청에 불필요하므로 추가하지 않는다. 이는 사용자가 위임한 범위에서 구현자가 선택한 방식이다.

## 동작

- 더블클릭 기본값은 Live, 포트 8765, 기존 `CommonApplicationData/AirWaveAPMonitor/live`다. 실제 설정은 열린 웹 화면에서 한다. Demo는 명시적으로 선택한다.
- Kestrel 준비 후 기본 브라우저를 연다. 수집기 콘솔에는 주소와 종료 방법을 표시한다. 브라우저를 닫아도 수집은 계속되며 콘솔 종료로 수집기를 종료한다.
- 이미 실행 중인 동일 앱·모드·데이터셋이면 그 화면을 다시 연다. 다른 데이터셋이나 다른 프로그램의 포트는 재사용하지 않고 명확히 실패한다. 기존 데이터·자격 증명·서비스/예약 작업을 자동 변경하지 않는다.
- CLI 기존 명령은 그대로 작동한다. 새 desktop 옵션의 기본값만 Live로 보완하며 기존 백엔드 무인 실행에는 여전히 명시적 모드가 필요하다. `--no-browser true`는 자동 검사 등에서 브라우저와 대화상자를 생략한다.
- 경로에 한글·공백이 있어도 실행한다. 상대 cwd에 의존하지 않는다. 실패 시 숨겨진 채 종료하지 않고 대화상자/콘솔로 안내한다.

## 패키지

최상위: `AirWaveAPMonitor.exe`, `시작하기.txt`.
`app/`: 기존 self-contained 앱과 웹 자원.
`tools/`: 8개 PowerShell 운영 스크립트.
`docs/guides/`: 사용·운영 안내 및 설정 예제.
`docs/development/`: 개발·검증 기록.
`docs/measurements/`: 측정 JSON.
`metadata/`: VERSION.json, SHA256SUMS.txt (체크섬 경로는 ZIP 루트 기준).

서비스/예약 작업은 계속 `app/AirWaveApMonitor.App.exe`에 직접 등록한다. 도구 기본 실행 경로만 새 위치에 맞춘다. 과거 초기 진단 패키징은 기존 구성을 유지한다. 새 core 버전은 0.1.1이며 기존 v0.1.0 태그/파일은 보존한다.

## 검증과 한계

단위 테스트: desktop CLI/동일·다른 데이터셋/다른 포트 응답/브라우저 요청/실패. 패키징: 새 트리·필수 EXE·전체 체크섬·상대 문서 링크·운영 자료 배제·기존 아카이브 보존. Windows 기존 CI에서 실제 컴파일한 native EXE와 실제 ZIP을 한글·공백 경로에서 실행하고 준비/재실행/오류/서비스/예약 작업/복원을 검사한다. 자동 검사에서 브라우저 UI를 생략하면 Windows 실제 더블클릭·기본 브라우저 GUI·SmartScreen·조직 정책은 미확인으로 기록한다. 실제 AirWave/AD/장비 확인 범위는 이전 릴리즈와 동일하다.
