# 운영 기록과 수동 대장

**AP 통합 현황**에서 AP 이름·IP·위치로 검색해 장비를 선택한다. 카드에서 전체·Up·Down·미확인 조건을 바꿀 수 있다. 네 탭 모두 선택한 AP와 조회 회차를 기준으로 열린다.

| 탭 | 확인·작업 방법 |
|---|---|
| 상태 | 해당 회차의 상태와 마지막 유효 관측, 관측 공백, 최근 추이를 확인한다. |
| 장애·조치 | 같은 AP에서 여러 번 발생한 장애 중 한 사건을 골라 자동 감지·복구와 연결된 조치 기록을 조회한다. 작업 완료와 자동 복구 관측은 각 시각으로 보존한다. |
| 연결·전력 | AP 목록에서 받은 스위치·포트 참조와, 저장된 연결·전력 관측의 출처와 시각을 각각 확인한다. 실환경의 LLDP·PoE 상세 수집은 미지원이다. |
| 대장 | 관측 당시 저장된 대장 값과 자동 원본을 조회한다. **현재 등록 정보 편집**에서 현행 대장을 정정할 수 있다. |

여러 AP에 걸친 장애는 **장애·작업 이력 → 장애 사건**, 여러 장비를 대상으로 한 작업이나 설치 변경은 **전체 작업·변경**에서 조회한다. **AP·설치 대장**에서는 AP 검색, 설치 지점, CSV 가져오기를 사용한다. **수집 기록 → 수집 종류**에서 AP 상태·연결·이웃·전력 회차를 조회하고 각 행의 회차 번호를 눌러 상세를 연다. 연결·전력 수집의 제공 범위와 설정은 **연결 설정**에서 연다.

과거 회차와 사건에 표시되는 정보는 당시 저장된 자료다. 이후 작성한 조치 메모는 최신 이력에서 확인한다. 이전 버전에서 확정된 회차는 당시 수동 기록의 저장 순서를 검증할 수 없어, 해당 과거 조회에 근거가 확인되는 자동 이벤트만 표시한다.

## 감시 범위와 기준 대조

연결 설정의 **감시 범위와 기준 대조**에서 **발견한 전체 AP** 또는 **선택한 원천 AP ID**를 고른다. 선택 범위에는 유효 관측이 있었던 정확한 원천 ID를 한 줄에 하나씩 입력하고 변경 사유를 기록한다. 이름/IP로 대상을 추측하지 않는다. 이 설정은 로컬 감시 대상을 바꾸며, 화면 검색·상태 필터와는 별개다. AirWave 원격 폴더 API 필터를 설정하는 기능은 아니다.

선택한 범위 정의와 변경 이력은 수집으로 발견하는 기대 대상 목록과 별도로 저장된다. 범위 밖 AP가 원천 응답에 포함돼도 선택 범위에 자동 추가하지 않는다. 수집 기록의 파싱 대수는 원천 전체이고 적용 대수는 선택 범위이므로 서로 다를 수 있다. 오류의 대상이 확실할 때만 범위 밖 오류를 구분하며, 공통 오류나 응답 실패는 숨기지 않는다. 필드별 의미는 [자료의 의미](DATA_DICTIONARY.md)를 참고한다.

범위 변경은 다음 수집부터 적용한다. 범위·설정 버전과 당시 정의·사유가 남고 새 기준은 잠정으로 돌아간다. 범위에서 빠진 AP의 기존 사건을 복구로 바꾸거나 과거 회차를 삭제하지 않는다. **발견한 전체 AP**로 돌아가면 알려진 대상과 새로 유효하게 발견한 AP를 다시 감시한다. 개별 AP의 명시적 제외·추적 종료 정책은 별도로 유지된다.

현재 설정의 수집이 확정되면 **이 입력의 대조 대상 원천 AP ID**를 실제 API 권한·관리 대장·물리 재고와 대조한다. 직접 대조한 대수와 방법·근거를 입력하여 기준 대조 결과를 저장한다. 표시 대수만 같다고 전체 장비 확인을 대신하지 않는다. 대조 회차·설정이 바뀌면 저장을 거부하므로 입력을 보관하고 최신 기준을 다시 읽어 검토한다. 새로운 대상이 발견되면 이전 확인을 새 목록 전체의 확인으로 확대하지 않는다.

대조 저장 후에는 새 설정의 다음 수집 결과를 확인한다. 그전의 **새 설정 관측 대기**는 대조 기록이 사라졌다는 뜻이 아니다. 과거 회차의 잠정/확인 상태는 당시 기록 그대로 남는다. DB를 복원해도 현재 설정의 범위 정의와 대조 이력을 과거 백업의 설정으로 되돌리지 않는다.

범위나 대조 입력을 작성 중에는 일반 상태 갱신이 입력과 기준 버전을 바꾸지 않는다. **입력을 버리고 서버 범위 다시 읽기**는 현재 초안을 버리는 명시적 동작이다. 기존 회차는 수집 기록에서 선택해 당시 범위·기준 상태로 조회할 수 있다.

과거 조회는 schema 6의 공유 저장 방식과 schema 5 이하의 기존 행을 같은 화면에서 읽는다. 저장 공간을 줄이려고 과거 행이나 참조를 직접 삭제하지 않는다. 변경한 현재 대장·배치를 과거 회차에 소급 적용하는 기능도 아니다.

## 수동 정보와 감시 정책

이름·위치·자산 정보 등을 입력하고 필요한 항목만 **수동 우선 표시**로 선택한다. 자동 원본과 확인 시각은 그대로 남는다. 빈 칸은 기존 값을 지우지 않는다. 삭제하려면 **등록값 명시 해제**와 사유를 입력하고, 그 값을 수동 우선으로 사용했다면 우선 표시도 해제한다.

저장한 등록은 즉시 조회할 수 있지만 관측 현황에는 **다음 AP 수집**부터 반영된다. 과거 회차·장애 스냅샷·그 회차의 CSV는 바뀌지 않는다. 장비 교체가 감지되면 이전 장비의 수동 대장과 배치는 새 장비로 자동 승계되지 않는다.

관리 상태는 다음처럼 사용한다.

| 선택 | 다음 수집부터 적용되는 의미 |
|---|---|
| 운영 · 감시 재편입 | 명시적으로 감시를 다시 시작한다. 종료된 감시는 새 감시 구간이 된다. |
| 계획 작업 | 계획 표시를 남기며 자동 상태 관측과 장애 기록을 계속한다. |
| 감시 제외 · 일시 제외 | 기존 열린 사건을 유지하고 새 상태 판정을 잠시 제외한다. |
| 감시 제외 · 추적 종료 / 철거 | 사유를 남기고 추적을 종료한다. 복구로 기록하지 않는다. |

자동 응답이 도착해도 사용자가 정한 제외·종료를 자동으로 취소하지 않는다. 종료에서 일시 제외로 바로 바꾸지 말고 필요한 경우 **운영 · 감시 재편입**을 선택한다.

## 설치 지점과 작업

**설치 지점**에서 지점을 등록하고 ID·현재 버전을 확인한다. AP의 현재 등록 정보에서 그 지점 ID·버전·배치 변경 사유를 입력한다. 지점을 비우고 저장하면 배치를 해제한다. 이동·해제는 이전 관계와 사유를 남긴다. 등록 시각과 알고 있는 실제 작업 시각은 구분한다.

**작업·메모**는 예정·실시·취소 상태, 내용·결과·원인 확인 상태와 여러 대상을 기록한다. AP 상세에서 시작하면 선택한 AP·장비 세대가 입력된다. 추가 대상은 정확한 AP·세대·사건 또는 지점 ID로 지정한다. 이름이나 IP가 같다는 이유로 대상이 합쳐지지 않는다. 정정·취소 때는 사유를 입력하며 이전 버전은 계속 조회할 수 있다. 작업 기록만으로 장애가 복구되지는 않는다.

자동 교체 감지는 우선 확인 필요로 표시된다. 두 장비 세대를 정확히 대상으로 지정한 실시 작업을 기록한 뒤 해당 감지의 **교체 작업 확인**에서 작업 ID·현재 버전·근거를 연결한다. 원래 자동 감지와 확인 기록은 각각 보존된다. 이전 세대의 열린 지점 등록은 현재 장비의 배치로 표시하지 않는다.

다른 창의 변경이나 DB 복원으로 저장이 충돌하면 입력은 유지된다. 내용을 확인하고 **서버 등록 다시 읽기**, **지점 다시 읽기**, **저장된 작업 다시 읽기** 등으로 최신 기록을 읽은 뒤 다시 편집한다. 다시 채우기를 선택하면 현재 미저장 입력이 사라지므로 필요한 내용을 먼저 보관한다.

## CSV 가져오기

UTF-8 CSV, 최대 4 MiB·5,000행을 사용한다. 다음 예시의 AP ID는 실제 화면의 내부 AP ID로 교체한다.

```csv
ap_id,name,site,asset_tag,manual_preferred_fields,notes
11111111-1111-1111-1111-111111111111,등록 이름,사업장 A,ASSET-001,name,대장 메모
```

내부 `ap_id`, 유일한 자동 `serial_number` 또는 `wired_mac`로 연결한다. 여러 식별자를 함께 쓰면 모두 같은 AP를 가리켜야 한다. 중복·모호·불일치 행은 적용하지 않는다. 이름·IP만으로 연결하지 않는다. 상태·LLDP·전력 열은 가져올 수 없다.

추가 등록 열은 `ip_address`, `model`, `firmware`, `building`, `floor`, `zone`, `detail`, `raw_location`, `folder`, `group`, `controller_id`, `controller_name`, `controller_ip`, `switch_name`, `switch_ip`, `port_name`, `ap_interface`다. `installation_point_id`는 이미 등록된 지점만 지정한다. 관리 상태는 `management_status`와 `management_reason`으로 입력한다. 값은 `Operating`, `PlannedWork`, `MonitoringExcluded`, `Decommissioned`를 사용한다.

`manual_preferred_fields`와 `clear_fields`는 열 이름을 세미콜론으로 구분한다. 명시 해제에는 `clear_reason`이 필요하다. 우선 표시를 모두 해제하려면 `manual_preferred_fields=none`을 사용한다. 빈 값은 변경하지 않는다는 뜻이다.

1. **파일 미리보기**에서 연결 대상·이전값/새값·행별 오류를 확인한다. 이 단계는 대장을 적용하지 않는다.
2. 적용할 유효 행만 선택하고 **선택한 행 적용 내용 검토**를 누른다.
3. 검토한 행 번호와 내용을 확인한 뒤 **검토한 행 적용**을 누른다.

미리보기 이후 대상·설정·배치·등록값이 바뀌거나 DB가 복원되면 선택 행 전체의 적용을 거부한다. 파일을 다시 미리보기하고 검토한다. 일부 행만 몰래 저장하지 않는다. 가져온 정보의 출처는 **가져오기**로 남으며 자동 관측을 바꾸지 않는다.

현황의 **CSV 내보내기**는 선택 회차와 전체 필터 결과를 사용한다. 첫 `QueryContext` 행에 조회 조건·회차·시각을 남기고 다음 `Ap` 행에 장비 자료를 담는다. 0대 결과도 조건 행이 있으므로 장비 행을 셀 때에는 `RecordType=Ap`를 기준으로 한다. 자동 원본·수동 등록·버전·출처·당시 배치 근거를 함께 담으며, 수식으로 해석될 수 있는 셀에는 방어용 접두어를 붙인다. 실제 사내 대장·DB·계정 자료를 외부로 올릴 필요는 없다.
