# 연결·LLDP·전력 관측

연결·전력은 AP 상태 수집과 구분되는 부가 관측이다. 이 안내는 해당 기능이 포함된 버전의 사용·해석 기준이다. 설치본의 제공 범위와 통합·Windows 검증 결과는 [개발 진행 및 검증 기록](../DEVELOPMENT_STATUS.md)과 `metadata/VERSION.json`에서 확인한다. 문서나 메뉴가 있다는 사실은 실제 AirWave 필드 제공 확인을 뜻하지 않는다.

## 먼저 확인할 제공 범위

기본값은 **연결·이웃 수집 꺼짐, 전력 수집 꺼짐, 상세 주기 15분**이다. AP 상태 수집은 별도 기본 주기 5분이다. 주기는 1~60분 범위다.

[CONFIGURATION_EXAMPLE.json](CONFIGURATION_EXAMPLE.json)은 이 네 기본값만 담은 참고 예시다. 앱이 자동으로 읽는 파일이나 API에 그대로 보낼 요청 본문이 아니며, `profile.json`·`appsettings.json`으로 바꾸어 넣지 않는다. 서버·계정·대상 ID나 비밀은 포함하지 않는다. 실제 변경은 현재 설정을 읽은 화면에서 저장한다.

| 표시 | 의미와 다음 동작 |
|---|---|
| 미검증 | 실제 프로필·계정·장비 유형·필드 계약이 확인되지 않았다. Live 수집을 활성화하지 않는다. |
| 제공 확인 | 해당 조건에서 필요한 의미·단위·시각·범위 근거가 확인된 필드다. 코드 지원·사용 설정·현재 오류 상태도 함께 확인한다. |
| 미지원 확인 | 해당 조건에서 지원되지 않는다는 근거가 있다. 빈 값 한 번이나 통신 오류와 구분한다. |
| 비활성 | 사용자가 수집을 켜지 않았다. 과거 값이 있으면 원래 시각의 기록으로 읽는다. |
| 예정 없음 | 현재 실행할 수 있는 수집이 예약되지 않았다. 비활성·미검증 등의 이유를 함께 확인한다. |

**현재 Live 연결·LLDP·PoE 전송 어댑터는 미구현·미검증이며 자동 수집을 켤 수 없다.** 공식 AP 상세 문서의 인터페이스 상태 예시는 유선 LLDP·PoE 계약을 증명하지 않는다. 설정 파일 수정, 직접 스위치 접속, 인증서 검증 해제로 우회하지 않는다. 필요한 원천 필드·권한·시각·단위 확인은 [사내 확인표](ONSITE_VALIDATION.md)에 별도로 기록한다.

## Demo에서 실행

실제 계정 없이 [Mac Demo](MAC_DEVELOPMENT.md) 또는 Windows Demo로 시작한다. 연결·전력 메뉴가 포함된 설치본에서 다음 순서로 확인한다.

1. **연결 설정 → 연결·전력 제공 범위와 설정 → 수집·제공 범위**에서 Demo 출처와 필드별 제공 근거를 확인한다.
2. **연결·이웃 수집 사용**, **전력 수집 사용**과 **상세 수집 주기 (분)**을 정하고 **상세 수집 설정 저장**을 누른다. 두 수집은 독립적으로 선택한다.
3. **이 종류 지금 수집**을 눌렀다면 요청 수락과 완료를 구분한다. **수집 기록 → 수집 종류**에서 해당 종류의 확정 결과를 확인한다. AP별 연결 근거를 먼저 보려면 연결·이웃 결과를 확인한 후 전력 결과를 확인한다.
4. **전력 표본**에서 지표·조회 시각·원천 장비/인터페이스로 필터링한다. 서로 다른 지표는 합산하지 않는다.
5. AP 상세·사건의 **보존 기간 내 전력 표본 보기**는 선택한 회차·대상 기준으로 확인한다. **전체 대상의 최신 표본 조회**는 별도의 현재 조회다.

설정 충돌 메시지가 나오면 미저장 입력을 보관하고 **저장된 상세 설정 다시 읽기**로 최신 값과 비교한다. **서버 값으로 다시 채우기**를 선택하면 현재 미저장 입력을 버린다. Demo의 가상 제공 확인·측정값·연결 기간은 실제 AirWave 응답 예시나 실장비 증거가 아니다.

## 수집 결과를 읽는 순서

AP, 연결·이웃, 전력 각각의 **최근 시도**, **최근 유효 확정**, **최근 완전 확정**, **최근 결과**, **다음 수집**, **품질 공백**, **저장 복구 대기**를 확인한다. 부가 수집 실패가 AP의 성공·마지막 유효 시각을 되돌리지는 않는다.

AP 수집이 대기하면 진행 중인 부가 요청의 경계에서 AP 수집을 우선한다. 부가 관측은 얻은 근거와 미조회 범위를 구분하므로 일부만 확인된 결과가 나올 수 있다. 미조회 포트의 이웃이 없다고 판정하지 않는다. 저장 복구 대기 상태에서는 새 성공을 가정하지 말고 결과·오류 범주를 확인한다.

상세 회차의 적용 범위 `Current`(현재 반영), `HistoricalOnly`(과거 기록만), `RejectedBinding`(대상 불일치)는 의미가 다르다. 예전 설정·장비 세대의 늦은 응답이 기록됐어도 현재 연결·현재 성공 시각이 갱신됐다는 뜻은 아니다. 진단·로그인 성공 역시 상세 수집 완료와 다르다.

## 연결·이웃 관측

- 같은 AP에 복수 연결이 있을 수 있다. 원천 장비·포트·상대 장비·발견 프로토콜·관측 방향을 각각 읽는다.
- **LLDP 최신 원천 관측**은 해당 원천 시각의 관측이다. 양방향 정상, 계속 연결됨, 내부 AP 귀속까지 증명하지 않는다.
- AP 목록의 연결 참조, 프로토콜 미상, CDP, 포트 Up, 전력 공급 On, LLDP 협상 지원을 LLDP 관측으로 바꾸어 읽지 않는다.
- **기대 이웃 미관측**은 성공·완전한 해당 포트 범위와 충분히 최신인 원천 근거가 있을 때의 판단이다. 케이블 제거·AP Down·원인 확정과 다르다.
- 부분·실패·미확인 응답에서는 이전 유효 연결을 참고로 유지할 수 있다. 원래 원천 시각과 공백 표시가 있으며 최신 확인으로 보지 않는다.

포트의 **관리 상태**와 **운용 상태**도 다르다. Dormant·NotPresent·LowerLayerDown 같은 원천 상태를 모두 AP Down으로 합치지 않는다. 원문과 각 필드의 제공·유효성을 확인한다.

## 전력 표본과 귀속

**AP 소비전력**, **스위치 포트 실제 전력**, **요청·할당·예약·최대 전력**은 서로 다른 지표다. 원문 값·단위와 검증된 W 값을 구분한다. 공급 상태·공급 방식·오류 횟수·LLDP 협상 지원은 별도 상태 정보다.

W와 검증된 mW만 전력 값으로 비교한다. dBm은 RF, Wh/kWh는 에너지다. 원문 단위 미확인·누락·잘못된 값은 **0 W가 아니며**, 원시 표본으로 누적 에너지나 요금을 계산하지 않는다. 수치가 매번 달라진다고 매번 운영 변경 사건이 생성되는 것은 아니다.

**AP 귀속 미확인**, **후보 충돌**, **연결 근거 지연**, **당시 대상 범위 밖**은 표본의 측정 지점과 AP 연결 근거가 충분하지 않다는 뜻이다. 현재 포트에 연결된 AP를 대신 붙이지 않는다. 직접 AP 소비전력도 측정 시점이 확인된 장비 세대·감시 구간 안에 있어야 한다. 과거 값이 늦게 도착하면 당시의 명시적 근거가 있는 경우만 당시 세대에 귀속한다.

귀속 상세에 선택된 연결·장비 세대·감시 구간·배치·지점 버전이 있으면 그것이 해당 표본의 저장 근거다. 이후 이동·교체·수동 대장 변경으로 기존 표본을 새 대상에 소급 이전하지 않는다.

## 과거 자료와 만료

과거 AP 회차와 장애 감지/복구 스냅샷에는 당시 저장돼 있던 근거가 들어간다. 후속 수집으로 과거 빈 값을 채우지 않는다. 스냅샷과 별도 원시 표본 조회의 보존 범위는 다를 수 있다.

수치 표본의 기본 보존은 30일이다. 조회 필터와 보존 기준은 앱의 **조회 시각**이며 원천·검증된 측정 시각은 따로 표시한다. 실제 정리 기준과 **만료 가능 표본** 표시를 확인한다. 빈 구간은 미측정·미제공·미확인·만료 중 무엇인지 수집 기록과 함께 판단하며 0 W나 공급 중단으로 해석하지 않는다.

일반 AP 회차의 원시 전력 상세는 30일 정리 후 만료될 수 있으며 만료로 표시한다. 사건에 복사한 스냅샷과 연결·이웃·포트·전원 상태 전환은 원시 수치 표본과 별도로 보존한다. 수집·공백 상세 90일 정리 후에도 과거 조회에 필요한 근거와 열린 사건·미종결 공백은 유지한다. 세부 의미는 [자료 사전](DATA_DICTIONARY.md)을 참고한다.

## 확인이 안 될 때

| 상황 | 확인할 항목 |
|---|---|
| 버튼이 비활성 | 실행 모드, 필드 제공 근거, 사용 설정, 일시정지·인증 차단·저장 복구 대기 |
| 조회는 최근인데 이웃은 지연 | 원천 시각과 의미; 같은 오래된 자료를 다시 읽은 것인지 |
| 전력 값이나 AP 귀속이 없음 | 지표·단위·측정 시각·세대 기간·당시 연결 근거·공백·보존 기간 |
| AP는 성공인데 상세는 실패 | 해당 상세 종류의 결과·오류 범주·실행 계정의 권한 |
| 메뉴나 자료를 제공하지 않는 패키지 | `metadata/VERSION.json`과 [개발 기록](../DEVELOPMENT_STATUS.md)의 포함 범위 |

외부에 실제 계정·쿠키·원문 XML·운영 DB를 올릴 필요는 없다. 현장에서는 버전·회차·오류 범주·기대값과 실제값을 조직의 기록 위치에 남긴다.
