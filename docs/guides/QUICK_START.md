# AirWave AP Monitor — 3분 사용법

대상: v0.1.3-preview.9 Windows 현장 검증용 ZIP.

## AP 상태 확인
1. 프로그램의 **AP 현황**을 엽니다. 마지막 유효 수집 시각과 수집 성공 여부를 확인합니다.
2. **장애**는 해당 회차에서 Down을 확인한 상태이고, **미확인**은 충분한 근거가 없어 상태를 확정하지 못한 경우입니다. 미확인을 Down으로 추정하지 않습니다. 전체 수집 실패 역시 Down 0대를 의미하지 않습니다.
3. 이름이나 IP로 검색하면 정상 AP까지 조회할 수 있습니다.

## 장애 확인과 조치 메모
1. Down AP를 선택하면 현재 장애 사건의 **장애·조치**가 열립니다.
2. 감지 시각과 AP 이름을 확인하고 조치 내용을 입력하여 저장합니다. 같은 AP라도 사건이 달라지면 별도 메모가 됩니다.
3. 현장 작업 완료와 실제 Up 관측·복구 확인은 별개입니다. 수동 메모가 자동 상태를 덮어쓰지 않습니다.

## 수집 기록의 오류
**관리 → 수집 기록**에서 성공 / 일부 확인 / 실패 / 중단을 구분합니다. 반복되는 원천 제외 경고는 **AP 분류 미검증 284건**처럼 합쳐 표시하며, ‘제외 사유·표본 ID 보기’에서 사유별 건수와 표본 원천 장비 ID(최대 3개)를 확인합니다. 제외 건수는 Down AP 대수가 아닙니다. 실제 AP 포함 여부는 AirWave 화면과 대조해야 합니다. HTTP 403은 자동 재로그인하지 않습니다.

## 관리 메뉴
- **장애·작업 이력:** 전체 장애 사건과 여러 AP에 걸친 작업
- **AP·설치 대장:** 사용자 등록 정보, 설치 지점과 CSV 가져오기
- **연결 설정:** IP·포트, Windows DPAPI 계정, HTTPS 지문, 연결 진단, 감시 범위
- **사용법·업데이트:** 화면별 도움말, 실행 상태, 안전 교체 절차

Live에서 LLDP·PoE 자동 수집은 API 제공 근거가 검증될 때까지 비활성입니다. Demo 자료는 실제 운영 관측이 아닙니다.

## 안전한 진단 정보 내보내기

관리 → 연결 설정의 **민감정보 제외 · 안전 진단 보고서**에서 복사 또는 JSON 저장을 선택합니다. 파일은 AP 상태·건수, HTTP 상태, TLS 결과 범주 등 허용된 값만 새로 구성하며 사내 주소·계정·비밀번호·인증서 지문·원천 로그를 복사하지 않습니다. 수집 기록이 없으면 Down 0대로 기록하지 않고 미확인으로 표시합니다.

실행 패키지 버전은 ZIP의 VERSION.json에서 읽습니다. 개발 환경처럼 메타데이터가 없는 경우 미확인으로 표시합니다.

새 프로그램으로 교체하려면 [업데이트 체크리스트](UPDATE_CHECKLIST.md) 및 [최초 연결 안내](FIRST_CONNECTION_KO.md)를 확인하세요.
