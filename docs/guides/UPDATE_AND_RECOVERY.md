# 업데이트·백업·복원

프로그램 버전 폴더와 영구 데이터 폴더를 분리한다. 기존 패키지와 데이터를 유지하고, 검증된 백업을 만든 후 새 버전으로 전환한다. 같은 로컬 디스크의 백업은 그 디스크 자체의 손실을 보호하지 않는다.

## 일일 백업과 수동 백업

수집기가 실행 중일 때의 일일 백업은 SQLite 온라인 백업 API를 사용한다. 성공 검증된 최신 7개 일일 백업을 유지하며, 새 백업이 실패했다고 이전 정상 백업을 먼저 지우지 않는다. 업데이트 전 백업은 별도로 보관한다. DB가 WAL 모드인 동안 `monitor.db`만 파일 복사하여 백업하지 않는다.

수동 CLI 작업은 데이터 폴더의 독점 잠금을 요구한다. 화면의 일시 중지나 브라우저 종료만으로는 잠금이 해제되지 않는다. 선택한 서비스·예약 작업 또는 대화형 수집기를 완전히 정지한 뒤, 데이터에 접근할 수 있는 운영 계정으로 실행한다.

```powershell
# 서비스 방식 예시. 예약 작업 방식이면 해당 작업만 중지한다.
Stop-Service -Name AirWaveAPMonitor
(Get-Service -Name AirWaveAPMonitor).WaitForStatus('Stopped', [TimeSpan]::FromSeconds(30))
.\tools\Backup-Restore.ps1 -Operation pre-update-backup -Mode live `
  -DataDirectory 'C:\ProgramData\AirWaveAPMonitor\live'
```

출력 JSON의 백업 경로·SHA256·데이터셋·스키마·시각을 운영 기록에 남긴다. `backup`은 일반 수동 백업, `pre-update-backup`은 업데이트 전 별도 백업이다. DB와 검증 manifest를 함께 보관한다. DB 백업은 `profile.json`, 데이터 모드 표시자, DPAPI 자격 증명 파일을 되돌리지 않으며 원문 자격 증명·세션 토큰을 포함하지 않는다. 설정과 계정의 보호·이전은 조직 정책에 맞춰 별도로 다룬다.

## 업데이트

실행 중인 프로그램의 **사용법·업데이트** 메뉴에서 상태를 확인할 수 있지만, 이것은 실행 중지나 업데이트 전 별도 백업을 대신하지 않는다. [안전 교체 체크리스트](UPDATE_CHECKLIST.md)를 적용한다.

현행 Windows ZIP에서는 최상위 `AirWaveAPMonitor.exe`로 대화형 실행한다. 관리 스크립트는 `tools/`로 이동했지만 데이터 경로와 DB 스키마는 유지한다. 이전 v0.1.0의 제거·백업 도구는 이전 ZIP의 루트에 있고, 새 버전의 도구는 새 ZIP의 `tools/`에 있다. 자동 시작 등록이 없는 일반 실행은 기존 수집기 종료·백업 후 새 EXE를 같은 계정/데이터 경로로 실행한다. 사용자 지정 경로·포트는 [실행 옵션](WINDOWS_RUN.md)을 따른다.

1. 새 ZIP·해시·소스 버전·검증 결과를 확인하고 **새 버전 폴더**에 전부 푼다. 이전 버전을 덮어쓰거나 삭제하지 않는다.
2. 현재 운영 방식·계정·서비스/작업 이름·포트·데이터 폴더·실행 경로·마지막 회차를 기록한다. 새 버전의 데이터 스키마 호환 범위를 확인한다.
3. 실제 수집기를 정지한다. 기존 버전에서 `pre-update-backup` 성공과 검증 결과를 확인한다. 실패하면 전환을 진행하지 않는다.
4. 이전 버전 폴더의 제거 스크립트로 **앱 소유 자동 시작 등록만** 해제한다. DB·설정·백업·이전 패키지는 그대로 둔다.
5. 새 버전 폴더에서 같은 데이터 폴더·포트·계정으로 선택한 운영 방식만 등록·시작한다. 등록 실패 시 기존 데이터는 보존하고 원인부터 확인한다.
6. 실행 계정·DB 열기·이전 회차·열린 사건·최근 수집·성공 시각·백업 상태를 확인한다. 브라우저를 닫아도 새 회차가 기록되는지 확인한다.

업데이트가 스키마를 올렸다면 옛 실행 파일을 현재 DB에 곧바로 연결하지 않는다. 옛 버전이 새 스키마를 지원하지 않으면 시작을 거부한다. 롤백은 호환되는 실행 파일과 그 시점의 검증 백업을 선택하는 별도 복원 절차다. 복원으로 사라질 백업 이후 이력이 무엇인지 확인하고, 현재 데이터 폴더와 DB를 보존한다.

## 정지 상태 복원

```powershell
.\tools\Backup-Restore.ps1 -Operation restore -Mode live `
  -DataDirectory 'C:\ProgramData\AirWaveAPMonitor\live' `
  -BackupFile 'C:\ProgramData\AirWaveAPMonitor\live\backups\검증된-백업.db'
```

예시 파일명은 실제 성공 출력의 `backupPath`로 대체한다. 유효한 manifest·무결성·지원 스키마·모드·데이터셋 검사 후 원자적으로 교체한다. 잘못된 백업을 이유로 운영 DB를 자동으로 지우지 않는다. 앱이 실행 중이거나 데이터 폴더를 다른 프로세스가 소유하면 복원을 거부한다.

현재 DB가 손상됐거나 알려지지 않은 스키마이거나 WAL 확정이 불가능하면 이 제자리 복원은 중단한다. 원래 DB·WAL·SHM과 데이터 폴더를 그대로 보존하고 별도 복구 절차를 정한다. 정상 현재 DB를 교체할 때도 출력의 `preservedDatabasePath`에 이전 DB를 보존한다. 현재 프로그램은 손상된 폴더 전체를 자동 수리하는 도구가 아니다.

복원은 백업 이후 관측을 복구해 만들지 않는다. 복원 공백을 기록하고, 백업에 진행 중 회차가 있었다면 다음 시작 시 중단으로 처리한다. Live 복원 후 현재 계정 바인딩은 재등록 필요 상태로 보호한다. 실제 서비스/예약 작업 계정으로 시작한 앱의 설정 화면에서 AirWave 자격 증명을 다시 등록한다. 과거 백업을 복원했다고 이전의 인증 차단을 암묵적으로 해제하지 않는다. 다른 PC/계정에서도 DPAPI 재등록이 필요하다.

복원 후 기존 사건·과거 회차·공백·현재 데이터셋과 신규 수집을 대조한다. 테스트용 오류 주입이나 CI 재시작 결과가 실제 전원 차단·디스크 손상·사내 정책 검증을 대신하지 않는다.
