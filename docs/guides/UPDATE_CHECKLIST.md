# AirWave AP Monitor — 안전한 Windows 업데이트 체크리스트

대상: v0.1.3-preview.9 현장 검증용 ZIP. 실행/백업/복구는 수집 PC의 운영자가 직접 수행합니다.

## 1. 파일 검증
1. GitHub Releases에서 정확한 버전별 ZIP을 새 폴더에 내려받습니다.
2. 릴리스의 SHA-256을 아래 명령 결과와 대조합니다.

   `Get-FileHash -Path '.\AirWaveAPMonitor-v0.1.3-preview.9-win-x64.zip' -Algorithm SHA256`

3. ZIP 전체를 별도 폴더에 압축 해제하고 `metadata\VERSION.json`의 `version`, `source_commit`, `working_tree_dirty`를 확인합니다. `onsite_verified=false`는 실장비 현장 검증 대기를 의미합니다.
4. GitHub Windows CI 통과는 사내 Live 연결을 보증하지 않습니다.

## 2. 환경 기록
기존 ZIP과 데이터 폴더를 보존하세요. 이전 운영 버전, Live/Demo 모드, 실제 데이터 폴더, Windows 실행 계정, 수집기 포트, 서비스/예약 작업 이름, 마지막 유효 AP 수집 회차를 기록합니다.

프로그램 **사용법·업데이트**의 읽기 전용 요약은 마지막 수집과 자동 백업 상태를 보여주지만, 이는 업데이트 전 별도 백업 성공의 증거가 아닙니다. 사용자 정의 실행 경로나 데이터 폴더를 바꾸지 않습니다.

## 3. 완전 정지 및 사전 백업
1. 진행 중 수집 회차가 있다면 저장 확정 여부를 확인합니다.
2. 사용 중인 EXE, 서비스 또는 예약 작업을 **완전히** 정지합니다. 브라우저 종료나 앱의 일시정지는 충분하지 않습니다.
3. **기존 버전** 도구를 통해 독점 잠금 상태에서 사전 백업을 수행합니다. 경로는 사내 실제 데이터 폴더로 대체하세요.

   `.\tools\Backup-Restore.ps1 -Operation pre-update-backup -Mode live -DataDirectory 'C:\ProgramData\AirWaveAPMonitor\live'`

4. 백업 경로, SHA-256, 데이터셋, 스키마 및 백업 검증 성공 여부를 기록합니다. 실패하면 교체를 중단합니다. WAL 모드에서 `monitor.db` 한 파일만 복사하는 것은 검증된 백업이 아닙니다.

## 4. 새 버전 실행
새 ZIP을 풀어둔 폴더에서 기존과 **같은 Windows 계정/데이터 폴더/포트**로 실행합니다. 서비스와 예약 작업을 함께 등록해 같은 데이터를 두 번 수집하지 마세요.

이전 AP 회차·열린 장애·조치 메모·설치 대장·설정·DPAPI 자격 증명 상태, 신규 AP 수집 회차를 확인합니다. HTTP 403·제외 284건 문제는 별도로 보관하며 보안 검증을 우회하지 않습니다.

## 5. 문제 발생 시 복귀
- DB 및 프로필 스키마가 이전 버전에서 지원됨을 확인한 경우에만 이전 EXE 복귀를 검토합니다.
- 스키마가 새 버전에서 변경됐다면 이전 EXE를 현재 DB에 직접 연결하지 마세요. 검증된 이전 백업을 선택해 완전 종료 상태에서 복원해야 합니다.
- 백업 이후 수집·메모는 복원 시 유실될 수 있습니다. 현재 DB/WAL/SHM을 별도로 보존하고 영향 범위를 검토합니다.
- Windows 실행 계정이 달라지거나 DB가 복원된 경우 DPAPI 자격 증명을 다시 등록해야 할 수 있습니다.

AirWave 계정/권한·인증서·프록시, 실제 AP 대수와 분류 제외 항목, 장시간 수집과 Windows 재부팅/서비스 재시작 검증은 사내 PC에서 확인합니다.
