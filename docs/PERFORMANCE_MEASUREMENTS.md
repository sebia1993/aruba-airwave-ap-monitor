# 합성 AP 2,000·5,000대 측정

측정 소스: `4d9a822a9a7305cf0b83341c5fc10f5836663f33`. 추적 파일 변경이 없는 상태에서 각 대수를 별도 새 프로세스·빈 데이터 폴더로 실행했다. macOS 27.2 Arm64, .NET 10.0.15, Release 빌드다. 실제 AirWave·Windows·HTTP 처리량 측정은 아니다.

## 방법과 검증

`dotnet build tests/Performance -c Release` 후 `AIRWAVE_MEASUREMENT_COMMIT=<소스 커밋> dotnet tests/Performance/bin/Release/net10.0/AirWaveApMonitor.Performance.dll <대수> <새 출력 폴더>`로 재현한다. `tests/Performance/Program.cs`가 가상 XML을 실제 파서와 SQLite 트랜잭션에 전달한다.

두 대수 모두 9프레임의 전체 목록을 500행씩 끝까지 읽어 고유 대상 수와 각 AP 상태를 대조했다. 전체 Down/미확인 집계, 사건 중복 금지, 복구, 반복 변경, 과거 조회, 저장소 재열기와 백업·91일 뒤 정리 후 역사 보존 검사가 모두 통과했다. 저장소 재열기는 같은 프로세스의 새 객체이며 실제 프로세스 재시작 검사는 개발 기록에 따로 있다.

실행 DLL의 SHA256은 아래 원시 JSON의 `executedAssemblies`에 남겼다. 누적 할당량은 현재 메모리가 아니며, macOS에서 프로세스 lifetime peak 값이 제공되지 않아 `null`로 기록했다. 아래 메모리는 각 단계에서 읽은 working set이며 실제 최대 메모리 보장이 아니다.

## 한계와 원시 결과

- 각 대수는 한 번 실행했다. 반복 통계·SLA·장기 부하·실서버 지연·동시 HTTP·스케줄러 처리량의 검증이 아니다. 중복 실행 방지는 별도의 coordinator 회귀로 확인한다.
- 이 도구는 AP 상태 경로다. 연결/전력은 실제 runner의 별도 2,048대·12,288표본 회귀 및 실제 Demo 브라우저로 검증했다. Live 부가 어댑터는 미구현·비활성이다.
- 측정용 DB와 백업은 공개하거나 반입 ZIP에 포함하지 않는다. 원시 JSON에는 합성 집계와 측정값·실행 파일 해시만 있다.
- [2,000대 원시 JSON](measurements/2026-11-16-ap-2000.json), [5,000대 원시 JSON](measurements/2026-11-16-ap-5000.json). 이 합성 측정 JSON은 ZIP에도 포함하며 운영 DB·백업은 포함하지 않는다.
