# Aruba AirWave AP Monitor

**핵심 목표는 AirWave를 주기적으로 조회하여 Down AP 현황을 추적하는 것입니다.** 수집 PC 한 대에서 이번 Down, 신규 Down, 미복구, 복구 확인과 반복 이력을 조회합니다. 정보·연결 변경, 장비 교체와 작업·조치 기록은 이 감시와 조사를 지원합니다.

**현재 상태: Task 1~8의 자동 감시·현황/CSV·장애/운영 이력·수동 대장/CSV·설치 지점/작업·Windows 운영·백업/복원을 구현하고 Windows CI를 통과했습니다. 확인된 개발 진행률은 92%입니다. Task 9 조건부 연결/전력 관측과 Task 10 최종 인수 검증을 이어갑니다. 실제 AirWave와 사내 Windows 11/AD 운영은 미확인입니다.**

실행: `./scripts/dev-mac.sh` → `http://127.0.0.1:8765`. [Mac 개발 안내](docs/guides/MAC_DEVELOPMENT.md)와 [작업별 진행·검증 기록](docs/DEVELOPMENT_STATUS.md)을 확인하세요. 초기 화면은 수집하지 않은 상태를 정상이나 Down 0대로 표시하지 않습니다.

## MacBook의 Codex에서 개발 시작

[MacBook Codex 작업 지시서](docs/superpowers/plans/2026-11-15-macos-codex-implementation.md)를 실행 기준으로 사용합니다. 기존 설계·모의화면을 연결하고, 파일 구성·인터페이스·10단계 구현 순서·20개 수용 검증·Windows 반입 패키지·보고 형식을 정리했습니다.

작업 지시서의 Task 1부터 순서대로 구현하고 있습니다. 현재 연결 설정·계정 등록·진단 화면을 실행할 수 있으며, 각 단계의 검증 결과와 개발 진행률은 진행 기록을 기준으로 확인합니다. 초기 Windows ZIP은 `./scripts/publish-win.sh`로 생성합니다. [초기 진단 안내](docs/guides/INITIAL_DIAGNOSTICS.md)는 패키지의 범위와 실행 방법을 설명합니다.

사내 접속 없이 실제 저장·상태 처리 코드를 사용하는 Demo 모드로 개발합니다. Mac 검증, Windows용 게시, Windows 실행, 사내 AirWave 확인을 나누어 기록하며, 실환경 확인을 기다리는 동안 가능한 구현은 계속합니다.

## 사용자 흐름 모의화면

[클릭형 모의화면 열기/다운로드](docs/prototypes/airwave-ap-monitor-mockup.html)

HTML 파일을 내려받아 브라우저에서 열면 별도 설치 없이 화면 흐름을 살펴볼 수 있습니다. 외부 리소스나 실제 AirWave 연결을 사용하지 않는 가상 데이터 기반 시안입니다.

- **사용 흐름 보기:** 최초 연결 설정 → 자동 수집 → Down AP 선택 → 조치·복구 추적.
- **수집 상황:** 정상 수집, 신규 Down, 복구, 전체 수집 실패, 일부 AP 누락을 전환합니다. ‘순서대로 재생’과 ‘지금 수집’도 가상 회차를 보여줍니다.
- **다운 AP 현황:** 미복구/신규/미확인 필터, 이름·IP·스위치 검색, 정렬, 계획 작업 숨기기, CSV 내보내기.
- **AP 상세:** 연결 스위치·포트, 장애·관측 이력, 조치 메모, 가상 전력·LLDP 참고 정보.
- **수집 기록:** 과거 회차의 현황을 열고 현재 현황으로 복귀합니다.

가상 장비는 2,048대입니다. 전체 조회 실패를 Down 0대로 표시하지 않으며, 일부 누락 예시는 이번 Down 7대·미복구 8대·미확인 3대를 구분합니다. 모의 입력·메모는 새로고침하면 초기화됩니다. PoE·LLDP 값은 화면 예시이며 실제 API 제공 여부는 미확인입니다.

이 시안은 핵심 감시 흐름 검토용입니다. 백그라운드 수집, 영구 DB 저장, 실제 인증 및 승인된 나머지 운영 이력 화면의 구현 완료를 의미하지 않습니다.

## 확정 범위

- 약 2,000대 이상 AP의 상태 자동 수집.
- 사내 Windows 수집 PC 한 대에서만 사용.
- AP Up/Down, 장애 감지와 복구 확인 이력에 집중.
- 사용자 요청으로 제안한 AP 식별·위치·컨트롤러·관리 항목과 여섯 종류 운영 이력을 모두 설계에 포함.
- AP 이름·IP·설치 위치·스위치·포트·펌웨어·컨트롤러 변경의 이전값과 새값 보존.
- 장비별 이력과 설치 지점별 교체·배치 이력 구분.
- 장애 당시 연결 정보를 각 정보의 출처·확인 시각과 함께 보존.
- 작업·점검·조치 메모, 정정 이력, 수동 정보·CSV 가져오기와 자동 관측의 구분.
- AP 장애와 수집 프로그램의 통신 실패를 구분.
- 재시작 후에도 현재 상태와 진행 중인 사건을 이어서 관리.
- 수집 회차별 Down 대수·해당 AP 목록과 이번 확인 불가 대상을 저장하고, 과거 이름·IP·연결 정보가 현재값으로 바뀌지 않도록 보존.
- PoE·LLDP 제공 여부나 상세 운영 기록 화면의 완성이 핵심 Down 감시의 시작을 막지 않도록 개발 순서를 분리.

## Down 현황의 기준

- 이번에 Down을 확인한 AP와, 마지막 상태는 Down이지만 이번에는 확인하지 못한 AP를 나누어 표시합니다.
- 새 Down과 복구는 AP별 유효 상태 전환으로 집계합니다. 처음 발견한 Down은 실제 시작 시각 미상으로 구분합니다.
- 전체 조회 실패를 Down 0대나 전체 정상으로 표시하지 않습니다. 기존 미복구 목록은 마지막 확인 시각과 함께 유지합니다.
- 회차별 대수와 목록은 같은 저장 결과를 사용합니다. 수집 실행 상세 로그 보존 기간 이후에도 회차별 현황은 유지합니다.
- 계획 작업 중 Down은 표시를 구분해 보존하고, 감시 제외는 별도 사유와 대수를 남깁니다.

## 스위치·PoE·LLDP 확인 범위

AirWave 8.2.14.0 공식 문서에는 AP의 연결 장비·포트와 전원·소비전력 표시, 지원 스위치의 PoE 상세 및 유선 이웃 조회가 설명되어 있습니다. 화면 구성과 제공값은 장비 종류에 따라 다릅니다.

- 연결 장비 표시만으로 LLDP 정상 유지라고 판정하지 않습니다. 이웃의 발견 출처와 원천 최신성을 확인합니다.
- AP 전력, 스위치 포트의 실제 전력, 할당·최대 전력을 구분하며 값이 없으면 0 W로 표시하지 않습니다.
- 자동 수집은 실제 공식 API의 필드·단위·시각·권한·조회 범위가 검증된 항목만 활성화합니다.
- AP 상태, 연결·이웃, PoE는 수집 결과·성공 시각을 분리합니다. 부가 조회 실패로 AP 상태를 Down으로 바꾸지 않습니다.
- 전력·이웃 데이터의 실제 API 제공 여부는 아직 미확인입니다. 설계의 저장·표시 지원과 연동 검증 완료를 구분합니다.

정확한 근거와 판정 규칙은 아래 설계 문서의 AirWave 연동 및 LLDP·포트·PoE 절에 정리했습니다.

## 기술 구성 — 구현 시작 기준

백그라운드 EXE가 AirWave 조회와 SQLite 저장을 담당하고, 같은 PC의 브라우저에서 현황과 이력을 조회하는 구성입니다. 작업 지시서는 C#/.NET 10 LTS, ASP.NET Core, SQLite를 구현 시작 기준으로 사용합니다.

기술 스택, 기본 수집 주기와 보존 정책은 설계자가 제안한 기본값입니다. 사용자가 해당 세부 기술을 직접 확정했거나 실제 성능이 검증되었다는 뜻은 아니며, 변경 시 이유와 영향을 기록합니다.

## 개발과 사내 검증의 분담

사용자는 **집의 MacBook에서 Codex로 개발하고, 프로그램을 사내 Windows 11 PC에 반입하여 직접 실환경 검증**합니다. MacBook 개발은 최신 사용자 요청에 따라 선택한 방향입니다.

| 단계 | 수행 범위 |
| --- | --- |
| 집의 MacBook에서 개발 | 가상 AirWave 응답으로 수집 처리, 상태 전환, 실제 이력·DB·화면과 오류 처리를 구현·검증 |
| 반입 전 Windows 확인 — 권장 | Windows용 배포물의 실행, 계정 보호, 자동 시작과 DB·로그 저장 확인 |
| 사내에서 사용자 검증 | 실제 API 로그인·대수·필드, PAC/프록시·인증서, 운영 계정과 상시 수집 확인 |

공통 앱은 Mac에서 실행되게 만들고, Windows DPAPI·서비스·예약 작업은 플랫폼 경계 뒤에 둡니다. Windows 확인 환경이 없으면 해당 실행 검증만 미실행으로 기록하고 구현을 계속합니다. Windows용 파일 생성과 Windows에서의 실행은 별도이며, 집의 Windows 확인도 사내 네트워크·인증서·운영 정책 확인을 대신하지 않습니다.

실제 사내 접속이나 원문 자료 제공을 집에서의 개발 선행 조건으로 요구하지 않는다. 개발용 가상 데이터와 사내 운영 데이터는 분리한다. 첫 사내 검증은 연결 진단과 한 회차 AP 수집을 우선 대상으로 삼아 실제 연동 차이를 확인한다. 반입 패키지에는 런타임·화면 자원과 버전·실행 안내를 포함하는 방향으로 준비한다.

기능 구현, 가상 응답 검증, Windows 실행 확인, 사내 사용자 검증의 완료 상태를 따로 기록한다. 실환경 미확인은 나머지 구현의 중단 조건으로 삼지 않으며, 실환경 검증 완료로 표시하지도 않는다.

## 데이터 관리

실제 접속 주소, 계정, 인증서, AP 목록, DB 및 실행 로그는 운영 PC에서 관리합니다. 저장소와 테스트에는 가상 예제 데이터만 사용합니다.

## 개발 방향

AP 기본 연결 → 상태·장애·회차별 현황 저장 → Down 우선 화면·검색·CSV → 자동 시작·백업·배포 순서로 핵심 감시를 먼저 완성합니다.

이미 승인된 운영 이력·작업 화면과 스위치·PoE·LLDP의 부가 수집은 공통 기반 위에서 병행·후속 구현합니다. 핵심 감시가 동작하는 상태와 전체 승인 범위의 완료를 구분합니다. 구체적인 구현 작업과 완료 기준은 MacBook Codex 작업 지시서에 정리했습니다.
