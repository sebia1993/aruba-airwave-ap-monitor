# Aruba AirWave AP Monitor

**핵심 목표는 AirWave를 주기적으로 조회하여 Down AP 현황을 추적하는 것입니다.** 수집 PC 한 대에서 이번 Down, 신규 Down, 미복구, 복구 확인과 반복 이력을 조회합니다. 정보·연결 변경, 장비 교체와 작업·조치 기록은 이 감시와 조사를 지원합니다.

**현재 상태: 설계 검토 단계입니다. 실행 가능한 제품이나 릴리즈는 아직 없습니다.**

## 확정 범위

- 약 2,000대 이상 AP의 상태 자동 수집.
- 사내 Windows 수집 PC 한 대에서만 사용.
- AP Up/Down, 장애 감지와 복구 확인 이력에 집중.
- 사용자 요청으로 제안한 AP 식별·위치·컨트롤러·관리 항목과 여섯 종류 운영 이력을 모두 설계에 포함.
- AP 이름·IP·설치 위치·스위치·포트·펌웨어·컨트롤러 변경의 이전값과 새값 보존.
- 장비별 이력과 설치 지점별 교체·배치 이력 구분.
- 장애 당시 연결 정보를 각 정보의 출처·확인 시각과 함께 보존.
- 작업·점검·조치 메모, 정정 이력, 수동 정보·CSV 가져오기와 자동 관측의 구분.
- AP 장애와 수집 프로그램의 통신 실패를 구분.
- 재시작 후에도 현재 상태와 진행 중인 사건을 이어서 관리.
- 수집 회차별 Down 대수·해당 AP 목록과 이번 확인 불가 대상을 저장하고, 과거 이름·IP·연결 정보가 현재값으로 바뀌지 않도록 보존.
- PoE·LLDP 제공 여부나 상세 운영 기록 화면의 완성이 핵심 Down 감시의 시작을 막지 않도록 개발 순서를 분리.

## Down 현황의 기준

- 이번에 Down을 확인한 AP와, 마지막 상태는 Down이지만 이번에는 확인하지 못한 AP를 나누어 표시합니다.
- 새 Down과 복구는 AP별 유효 상태 전환으로 집계합니다. 처음 발견한 Down은 실제 시작 시각 미상으로 구분합니다.
- 전체 조회 실패를 Down 0대나 전체 정상으로 표시하지 않습니다. 기존 미복구 목록은 마지막 확인 시각과 함께 유지합니다.
- 회차별 대수와 목록은 같은 저장 결과를 사용합니다. 수집 실행 상세 로그 보존 기간 이후에도 회차별 현황은 유지합니다.
- 계획 작업 중 Down은 표시를 구분해 보존하고, 감시 제외는 별도 사유와 대수를 남깁니다.

## 스위치·PoE·LLDP 확인 범위

AirWave 8.2.14.0 공식 문서에는 AP의 연결 장비·포트와 전원·소비전력 표시, 지원 스위치의 PoE 상세 및 유선 이웃 조회가 설명되어 있습니다. 화면 구성과 제공값은 장비 종류에 따라 다릅니다.

- 연결 장비 표시만으로 LLDP 정상 유지라고 판정하지 않습니다. 이웃의 발견 출처와 원천 최신성을 확인합니다.
- AP 전력, 스위치 포트의 실제 전력, 할당·최대 전력을 구분하며 값이 없으면 0 W로 표시하지 않습니다.
- 자동 수집은 실제 공식 API의 필드·단위·시각·권한·조회 범위가 검증된 항목만 활성화합니다.
- AP 상태, 연결·이웃, PoE는 수집 결과·성공 시각을 분리합니다. 부가 조회 실패로 AP 상태를 Down으로 바꾸지 않습니다.
- 전력·이웃 데이터의 실제 API 제공 여부는 아직 미확인입니다. 설계의 저장·표시 지원과 연동 검증 완료를 구분합니다.

정확한 근거와 판정 규칙은 아래 설계 문서의 AirWave 연동 및 LLDP·포트·PoE 절에 정리했습니다.

## 추천 구성 — 검토 중

백그라운드 EXE가 AirWave 조회와 SQLite 저장을 담당하고, 같은 PC의 브라우저에서 현황과 이력을 조회하는 구성입니다. 기술 후보는 C#/.NET 10 LTS, ASP.NET Core, SQLite입니다.

브라우저 UI, 기술 스택, 기본 수집 주기와 보존 정책은 설계 문서의 제안값이며 아직 사용자 확정 요구사항과 구분해서 관리합니다.

## 데이터 관리

실제 접속 주소, 계정, 인증서, AP 목록, DB 및 실행 로그는 운영 PC에서 관리합니다. 저장소와 테스트에는 가상 예제 데이터만 사용합니다.

## 개발 방향

AP 기본 연결 → 상태·장애·회차별 현황 저장 → Down 우선 화면·검색·CSV → 자동 시작·백업·배포 순서로 핵심 감시를 먼저 완성합니다.

이미 승인된 운영 이력·작업 화면과 스위치·PoE·LLDP의 부가 수집은 공통 기반 위에서 병행·후속 구현합니다. 핵심 감시가 동작하는 상태와 전체 승인 범위의 완료를 구분합니다. 구체적인 구현 작업은 설계 검토를 마친 뒤 별도 계획으로 작성합니다.
